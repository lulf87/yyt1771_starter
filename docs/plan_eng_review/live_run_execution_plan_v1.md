## Step 0: Scope Challenge

### State diagnosis

当前仓库处于“已有离线骨架，但主链仍未进入 live 实验执行”的状态。它不是从零开始，也不是适合大重写的阶段，更像：

- 主链能力不足
- 边界已经冻结
- 现有 replay / workspace 能证明很多层是可复用的

因此本轮工程策略必须是：

- **增量扩展**
- **复用既有模块**
- **只打通最小 live 闭环**

同时产品 framing 按 [office_hours_requirement_baseline_v1.md](../requirements/office_hours_requirement_baseline_v1.md) 锁定：

- `Commissioning Lane` 继续保留，但不是当前扩展的主线
- `Experiment & Analysis Lane` 是本轮 live run 扩展的主链
- replay / workspace 保留为离线验证与复盘能力，不反向定义 live run 的产品目标

不建议：

- 另起一套 run-engine 子系统
- 引入 WebSocket、事件总线、多进程采集这类高创新成本结构
- 一次性把多通道、角度模式、复杂复核工作台全部并入首版

### Minimum viable scope

本轮锁定的最小闭环是：

1. 相机 live 预览
2. freeze-first 的分析 ROI + 形变框 + 两点测量定义
3. 串口温控最小控制语义
4. live run 单循环采集
5. `Space1 + Temperature -> AFAS -> As/Af`
6. 结果与证据包落盘

### 2026-03-23 temporal-sampling addendum

基于
[live_capture_temporal_sampling_requirement_v1.md](../requirements/live_capture_temporal_sampling_requirement_v1.md)，
execution plan 额外锁定 4 条补充原则：

1. `setup preview fluidity` 和 `measurement cadence` 必须拆成两个 workstream。
2. `measurement_mode` 必须允许独立于 setup preview 的 camera acquisition profile。
3. `analysis_roi` / `metric_box` 不能代替 camera-side acquisition ROI。
4. `50 Hz synchronized measurement` 是新的 baseline gate；`100 Hz` 只保留为 stretch gate。

### Scope reduction decision

复杂度检查会触发，因为完整闭环至少涉及：

- 配置
- core 契约
- temp 适配
- vision extractor
- workflow orchestration
- storage artifact
- web routes
- web schemas
- 前端 setup/run UI
- tests

如果按“完整平台化”思路推进，会远超 8 个文件和 2 个新服务。

本次 review 的结论是：

- **接受 scope reduction**
- 只允许 3 个新的核心实现类/模块成为主轴：
  - `src/temp/lu92xx_modbus_rtu_controller.py`
  - `src/vision/metric_two_point_distance.py`
  - `src/workflow/live_run.py`

除此之外，其他改动都应是：

- 现有模型/契约扩展
- route/schema/config 补齐
- tests 镜像补齐

### Completeness check

本轮不接受下面这些“为了省事”的 shortcut：

- 用 JSON 数组直接返回 live 全帧图像
- 在 route 里直接写串口协议
- 在 workflow 里直接写 `As/Af` 算法
- tracking 失败时静默补点
- run 结束后只给一个温度值结果，不给证据包

完整版本和 shortcut 之间，本轮统一选择完整版本，但只限于最小闭环范围。

## Architecture Review

### 1. Module boundary lock

#### 1.1 `src.camera`

责任锁定为：

- 连接相机
- 应用相机参数
- 输出 `FramePacket`

不放进 `camera` 的内容：

- ROI 编辑
- 点位检测
- HTTP 编码
- run 状态判断

Recommendation:

- 继续复用 `HikGigeMvsCamera`
- 最多补 `configure()` / `open()` / `read_frame()` 的稳定行为
- 不新建 `camera_service` 或 `preview_service`

#### 1.2 `src.temp`

当前 `TempReader` 只有 `read()`，不满足“下发目标温度 + 启动输出 + 回读温度”。

Recommendation:

- 在 `src.core.contracts` 新增 `TempControllerPort`
- 由 `src.temp.lu92xx_modbus_rtu_controller.LU92XXModbusRtuController` 同时实现：
  - `TempReader`
  - `TempControllerPort`
- 实现锁定在 `LU92XX + RS485 + Modbus RTU`。
- 协议层优先使用已确认的 `03H` / `06H` / `10H` 语义。
- 真实业务寄存器地址、缩放规则、启停写法保持 profile-driven，
  不允许在 `workflow` 或 route 层硬编码。
- `set_target_temperature(celsius)` 的 public semantic 继续保持“目标温度”，
  即使底层设备寄存器在旧系统里更接近“停止温度”命名。
- `start_output()` 继续保持无参，但如果 LU92XX 最终是通过“写功率寄存器非零”来启动，
  则所需功率值必须来自 profile 配置，而不是 API 入参。

最小控制语义锁定为：

- `set_target_temperature(celsius: float) -> None`
- `start_output() -> None`
- `stop_output() -> None`
- `read() -> TempReading`

Rejected:

- 把温控控制塞进 `src.plc`
- 把串口命令直接写在 `src.workflow`

#### 1.3 `src.vision`

当前 `EndDisplacementMetricExtractor` 是“单点自由端位移”模型，不适合直接承接“ROI + 形变框 + 两点间距”。

Recommendation:

- 保留现有 `metric_end_displacement.py` 给 replay / 旧测试
- 新增 `metric_two_point_distance.py`
- 新 extractor 输入：
  - 分析 ROI
  - 形变框
  - 阈值策略
  - 前景极性
  - 忽略内部纹理开关
  - 初始两点或锁定两点
- 新 extractor 输出仍然是 `ShapeMetric`

但 `ShapeMetric` 需要扩展显式字段，不要只塞 `meta`：

- `analysis_roi`
- `metric_box`
- `point_a_px`
- `point_b_px`
- `tracking_quality`
- `validity`

Backward compatibility:

- 保留现有 `feature_point_px`，供旧 replay/detail 使用
- 新 live 链路只消费新字段

#### 1.4 `src.sync`

`src.sync` 保持“时间对齐器”身份，不升级成事件总线。

Recommendation:

- 第一版 live run 采用**单协调循环**
- `camera.read_frame()`、`temp.read()`、`vision.extract()` 在同一 coordinator tick 中串行执行
- `SyncHub` 仍然只负责聚合，不负责调度

Reason:

- 最小 diff
- 避免并发与时序 race
- 首版更容易写稳定测试

#### 1.5 `src.curve`

Recommendation:

- `src.curve` 新增 AFAS adapter，负责把 `SyncPoint` 序列转换成 AFAS 可消费的数据结构
- `As/Af` 结果计算只能落在 `src.curve`
- `workflow` 只调用结果，不内嵌切线法细节

#### 1.6 `src.workflow`

Recommendation:

- 保留 `session.py` 负责 mock/replay
- 新增 `live_run.py` 负责真实 run
- `WorkflowStateMachine` 必须升级，但不要把所有 UI 微状态都塞进 `SessionState`

Lock:

- `workflow` 只做 orchestration
- 不做图像分割
- 不做串口报文拼装
- 不做 `As/Af` 公式实现

#### 1.7 `src.storage`

当前 `SessionArtifactStore` 的“一 session 对应一个 JSON 文件”不适合 live 证据包。

Recommendation:

- SQLite 继续只存 summary index
- artifact 改成 per-session 目录

建议目录结构：

```text
<artifact_dir>/<session_id>/
  definition.json
  telemetry.csv
  result.json
  events.jsonl
  keyframes/
    first.jpg
    middle.jpg
    last.jpg
```

First version intentionally excludes:

- 全量原始帧逐帧落盘
- 实时视频文件封装

#### 1.8 `src.webapp`

Recommendation:

- `src.webapp.routes.session` 继续负责历史/回放/结果查看
- 新增 `src.webapp.routes.live_run`
- live mutable state 与 immutable history 分开

Namespace lock:

- `/api/system/*`：profile / precheck / probe
- `/api/runs/*`：live run draft, preview, definition, start/stop, status, telemetry
- `/api/session/*`：历史 summary、result detail、workspace data

Rejected:

- 把 live run 命令硬塞进现有 `/api/session/run-*`

### 2. State flow lock

#### 2.1 Separate backend run state from UI step

Current risk:

- 现有 `SessionState` 只有 `created/precheck/running/completed/failed`
- 它不足以表达 setup/run/review 的真实状态

Recommendation:

- `SessionState` 继续作为历史摘要态
- 新增 `RunStatus` 作为 live mutable state

Suggested `RunStatus`:

- `created`
- `device_ready`
- `preview_ready`
- `definition_editing`
- `run_ready`
- `running`
- `stopping`
- `completed`
- `failed`
- `invalidated`
- `aborted`

UI 只展示映射后的 step，不反向驱动 domain state。

#### 2.2 Locked state machine

```text
created
   |
   v
device_ready
   |
   v
preview_ready
   |
   v
definition_editing
   |
   v
run_ready
   |
   v
running -----> invalidated
   |               |
   |               v
   |------------> stopping -----> aborted
   |
   v
stopping
   |
   v
completed

Any state -----> failed
```

Entry guards:

- `preview_ready` requires camera open + preview frame available
- `run_ready` requires temp connected + measurement definition locked
- `running` requires target temperature accepted + output started
- `start_output()` must succeed before state can enter `running`

Exit guards:

- `completed` requires artifact finalize + result finalize success
- `invalidated` means data captured but not trustworthy for auto result
- `aborted` is used for user stop or guard-driven stop after invalidation
- `failed` is reserved for infrastructure/protocol/storage errors, not operator stop

### 3. API contract lock

#### 3.1 Resource model

The mutable resource is `run draft`, not `session summary`.

Resource split:

- `run_id`: live mutable resource
- `session_id`: finalized historical record

`run_id` may become `session_id` at finalize time, or persist as the same identifier. First version may use one identifier, but the API semantics must preserve the distinction.

#### 3.2 Locked endpoints

```text
POST   /api/runs
GET    /api/runs/{run_id}
POST   /api/runs/{run_id}/preview/frame
POST   /api/runs/{run_id}/definition/auto-detect
PUT    /api/runs/{run_id}/definition
POST   /api/runs/{run_id}/start
POST   /api/runs/{run_id}/stop
GET    /api/runs/{run_id}/telemetry
GET    /api/runs/{run_id}/result
```

Recommended payloads:

`POST /api/runs`

```json
{
  "profile": "prod_win",
  "preset": "balloon"
}
```

Response:

```json
{
  "run_id": "run-20260321-001",
  "status": "created"
}
```

`PUT /api/runs/{run_id}/definition`

```json
{
  "analysis_roi": {"x": 0, "y": 0, "width": 1280, "height": 720},
  "metric_box": {"center_x": 640, "center_y": 360, "width": 900, "height": 120, "angle_deg": 12.0},
  "point_a_px": {"x": 210, "y": 320},
  "point_b_px": {"x": 980, "y": 402},
  "foreground_polarity": "dark_on_light",
  "threshold_mode": "adaptive",
  "ignore_internal_texture": true,
  "min_target_area_px": 200
}
```

`POST /api/runs/{run_id}/definition/auto-detect`

Purpose:

- server-side generate suggested `point_a_px` / `point_b_px`
- keep ROI / metric-box geometry validation in one place
- let UI support “自动建议点 + 手动微调” without duplicating detection logic client-side

`POST /api/runs/{run_id}/start`

```json
{
  "target_temperature_celsius": 75.0
}
```

Public semantic lock:

- request field stays `target_temperature_celsius`
- do **not** leak device-internal names such as “stop temperature” into API payloads
- if LU92XX mapping later confirms that register `0` is historically labeled as stop temperature,
  the adapter layer absorbs that translation

`GET /api/runs/{run_id}/telemetry`

```json
{
  "run_id": "run-20260321-001",
  "status": "running",
  "latest": {
    "timestamp_ms": 1711000000000,
    "temperature_celsius": 42.3,
    "space1_px": 181.2,
    "tracking_quality": 0.93
  },
  "curve": [
    {"timestamp_ms": 1711000000000, "temperature_celsius": 40.1, "space1_px": 179.0},
    {"timestamp_ms": 1711000000500, "temperature_celsius": 41.0, "space1_px": 180.0}
  ]
}
```

#### 3.3 Preview transport rule

Do not return live full frame as nested JSON pixel arrays.

Recommendation:

- `POST /api/runs/{run_id}/preview/frame` returns a downsampled JPEG or PNG response
- overlay rendering happens server-side for first version
- front-end polls at a low fixed rate

Rejected:

- WebSocket streaming in v1
- JSON pixel matrix in v1

## Code Quality Review

### 1. Avoid dict sprawl

Problem:

- anonymous dicts are acceptable for today's mock profiles
- they are not acceptable once live temp, vision, run, and analysis all join the contract

Recommendation:

- add typed config section models
- keep raw YAML only at loader boundary

### 2. Keep one orchestration class

Problem:

- splitting coordinator, sampler, tracker manager, preview manager, artifact manager into many new services would overbuild the first slice

Recommendation:

- `LiveRunCoordinator` owns the run loop
- helpers stay as plain functions or small private methods unless complexity proves otherwise

### 3. Keep hardware-specific parsing out of route layer

Recommendation:

- route layer only validates HTTP payloads
- protocol normalization and device errors stay in `workflow` + adapter layers

### 4. Preserve backward compatibility for replay/workspace

Recommendation:

- do not rename existing replay endpoints in the same PR
- add live run endpoints alongside them
- evolve `schemas.py` additively, not destructively

### 5. Prefer additive model evolution

Recommendation:

- extend `ShapeMetric`, `SessionSummary`, and schema responses additively
- do not repurpose fields like `feature_point_px` to mean “two points”

### Failure modes

| Codepath | Realistic failure | Test required | Error handling required | Silent failure allowed |
| --- | --- | --- | --- | --- |
| preview frame fetch | camera opens but returns empty frame | yes | yes | no |
| definition save | point outside ROI or box degenerate | yes | yes | no |
| auto-detect | suggested points fall outside metric box | yes | yes | no |
| run start | temp target accepted but start output rejected | yes | yes | no |
| temp mapping | profile still points at `264` but device actually needs `258` | yes | yes | no |
| acquisition loop | temp read blocks and loop stalls | yes | yes | no |
| tracking loop | points drift outside metric box | yes | yes | no |
| AFAS compute | insufficient valid points | yes | yes | no |
| artifact finalize | result saved but telemetry file missing | yes | yes | no |

Critical gap rule for implementation:
