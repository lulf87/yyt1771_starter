## Purpose

这份文档把新的：

`auto-live-preview -> Freeze -> rotated ROI -> ROI-local A-B -> live ROI tracking`

requirement 转成可执行工程计划。

它锁定 6 件事：

1. 当前 operator workflow 改动后，哪些后端契约保留，哪些前端动作被移除
2. ROI 旋转、灵敏度、当前温度、目标温度确认这些新要素放在哪一层
3. `A-B` 的自动求取和 live tracking 如何围绕单一 ROI 建模
4. 旧的 `Draw Window / Rotate Window / observation_window` 语义如何降级而不是继续主导实现
5. 测试与验收 gate 要怎么写
6. 分阶段实施顺序是什么

## Review Verdict

当前实现不能在旧的 `ROI -> A-B -> observation_window` plan 上继续局部打补丁后直接视为合规。

原因已经锁定：

- 当前用户流仍然暴露了 `Create Live Run / Fetch Preview / Start Live Preview`
- 当前 setup 仍把 `Draw Window / Rotate Window` 当成显式用户步骤
- 当前 auto detect 还停留在“为 `A-B` 和 window 服务”的上一轮几何模型
- 当前 live run 阶段也还没有明确把 ROI 当成唯一 tracking aperture

因此工程 verdict 是：

1. 必须把旧按钮流降级成内部实现细节，而不是 operator-facing workflow
2. 必须把 ROI 提升为 setup 与 tracking 的唯一主几何
3. 必须把 `A-B` 明确建模成 ROI-local horizontal detection 结果和 live-tracking overlay
4. 必须把 `Draw Window / Rotate Window` 从当前 UI 主流中移除
5. 旧 `observation_window` 契约可暂时保留在后端兼容层，但不允许继续主导当前实现

## 1. Architecture and Boundary Lock

### 1.1 `src.core`

锁定职责：

- final measurement definition contract
- ROI durable geometry
- point durable geometry
- sensitivity durable config

本轮新增或修订方向：

- `MeasurementDefinition` 需要显式承载：
  - `analysis_roi.center_x`
  - `analysis_roi.center_y`
  - `analysis_roi.width`
  - `analysis_roi.height`
  - `analysis_roi.angle`
  - `point_a_px`
  - `point_b_px`
  - `sensitivity`
- 当前 operator flow 不再要求 `metric_box / observation_window` 成为 primary durable geometry

锁定建议：

- 不做一次性 destructive field removal
- 旧字段可保留为 legacy-compatible / optional
- 新实现不得再要求前端设置它们才能完成 setup

### 1.2 `src.vision`

锁定职责拆成两类：

1. `ROI-local start-point detection`
   - 输入：frozen frame + rotated ROI + sensitivity
   - 在 ROI 本地坐标系的横轴上确定 object 左右边界点
   - 输出：initial `A-B`

2. `ROI-bounded live tracking`
   - 输入：live frame + final ROI + start `A-B`
   - 仅在 ROI 内跟踪形变
   - 实时刷新 `A-B`

锁定决定：

- 不再把“auto detect 起始点”和“后续 live tracking”混在一个隐式 path 里
- 可以共用 geometry / mask helper
- 但 API 语义必须拆开

### 1.3 `src.webapp`

锁定职责：

- app boot flow
- preview / freeze lifecycle
- ROI editor
- setup panel
- live overlay

新增 requirement-driven 责任：

- 页面加载后自动进入 live preview
- 自动创建或恢复当前 setup session
- `Freeze` 成为唯一 preview lifecycle 按钮
- 右侧参数面板切到 ROI-first：
  - center x / y
  - width / height
  - angle
  - sensitivity
  - current temperature
  - target temperature
  - confirm target action
- live run 期间实时刷新 `A-B` overlay

### 1.4 `src.workflow`

锁定职责：

- 消费 final saved definition
- 运行 live coordinator
- 负责 temp/controller start-stop-read
- 写 telemetry / result / artifacts

新增 requirement-driven 责任：

- workflow 只消费最终的 ROI 和起始点
- 不负责 UI 层的 ROI 拖拽、旋转手柄、或 sensitivity 编辑
- live run 期间允许把实时 `A-B` 更新通过 telemetry / detail channel 回传给前端

## 2. Operator Flow Lock

## 2.1 Frozen UI flow

新的 operator flow 锁定为：

1. app load
2. automatic live preview start
3. user presses `Freeze`
4. user draws / adjusts rotated ROI
5. system computes `A-B` inside ROI-local horizontal axis
6. user adjusts ROI or sensitivity as needed
7. system recaptures still + recomputes `A-B` on every geometry/sensitivity change
8. user confirms target temperature
9. user presses `Start Live Run`
10. live preview resumes and `A-B` updates continuously

## 2.2 Hidden compatibility policy

为了最小 diff，当前 plan 锁定：

- 后端 run/session 机制继续存在
- `POST /api/runs` 不立即删除
- `preview/frame` 和 `preview/stream` 机制继续存在

但这些不再以按钮暴露给 operator。

前端实现建议：

- 页面初始化时自动创建或恢复当前 setup run
- 自动启动 `preview/stream`
- `Freeze` 继续复用当前 `stop preview stream + keep last frame` 语义

## 2.3 Removed UI actions

当前 operator-facing UI 中必须移除：

- `Create Live Run`
- `Fetch Preview`
- `Start Live Preview`
- `Draw Window`
- `Rotate Window`

如果后端或前端内部暂时保留它们的实现，只能作为兼容层，不得继续作为用户主流程。

## 3. Data and API Contract Lock

## 3.1 Session bootstrap contract

前端 load 时必须能完成两件事：

- 获取或创建当前 setup run
- 自动启动 live preview

工程建议：

- 优先复用现有 `/api/runs` 创建逻辑
- 在前端 boot sequence 内自动调用
- 不新开第二套 setup bootstrap 协议，除非实现时证明现有路由无法保持清晰

## 3.2 ROI contract

`analysis_roi` 的当前 canonical contract 应升级为旋转矩形：

- `center_x`
- `center_y`
- `width`
- `height`
- `angle`

兼容策略：

- 如现有 API 仍是 `x/y/width/height`，允许在兼容层里保持旧字段
- 但 plan recommendation 是尽快在 schema/model 层加上中心点和角度的 canonical 表达

## 3.3 Sensitivity contract

新增 operator-facing field：

- `sensitivity`

它应进入：

- setup form schema
- saved definition
- auto-detect request
- live replay/detail contract（至少可回看已保存值）

## 3.4 Temperature UI contract

界面必须显式区分：

- `current_temperature_celsius`
- `target_temperature_celsius`
- `target_temperature_confirmed`

锁定决定：

- 当前温度显示为只读实时值
- 目标温度输入不代表已下发
- 必须存在显式“确认目标温度”动作

## 3.5 Live tracking contract

开始测试后，前端必须能获得实时 `A-B` 更新。

推荐契约：

- `telemetry` 或 detail/live snapshot 中返回：
  - current `point_a_px`
  - current `point_b_px`
  - timestamp

最小实现可先不把每一帧 `A-B` 落进最终 artifact bundle，但 UI 的 live overlay 必须能持续刷新。

## 4. Geometry and Tracking Lock

## 4.1 ROI-local detection model

auto-detect 的当前工程定义锁定为：

- 先把图像采样限制在 ROI
- 再在 ROI 本地坐标系内工作
- 只沿 ROI-local horizontal axis 求 object 左边界和右边界

明确禁止：

- 在全图世界坐标系中固定按水平或垂直找点
- 输出任意角度最长弦
- 继续要求 `observation_window` 先存在

## 4.2 Object model

本轮 requirement 假设当前 setup scene 满足：

- `blank - object - blank`

也就是说：

- ROI 左右两边主要是空白
- 中间是待测物体

灵敏度参数负责把：

- 网格 / 多孔 / 纹理目标

合并成稳定的 object mask，以便确定左右边界。

## 4.3 Recapture policy

任意以下输入变化都必须触发 still recapture + point recompute：

- ROI center
- ROI size
- ROI angle
- sensitivity

锁定建议：

- 对拖拽操作做 UI 级 debounce
- 但最终释放鼠标后必须保证完成一次真实重算

## 4.4 Live tracking policy

`Start Live Run` 后：

- 图像恢复 live
- ROI overlay 继续显示
- `A-B` 在 ROI 内实时更新

当前计划明确不要求：

- 在 live run 期间让用户继续交互式旋转 ROI

推荐锁定：

- live run 期间 ROI 几何视为已冻结
- 只更新 `A-B`

## 5. Implementation Strategy Lock

## 5.1 Minimal-diff strategy

本轮不建议推翻现有 run/session/preview API。

推荐策略：

1. 保留后端核心 API
2. 先改前端 boot flow 和 editor flow
3. 再在 schema/model 层补 ROI angle、sensitivity、temp confirm
4. 最后改 auto-detect 和 live tracking

这样可以把风险控制在：

- UI 行为重排
- geometry contract 扩展
- vision path 重构

而不是全链重写。

## 5.2 Legacy window deprecation

当前 plan 锁定：

- `metric_box / observation_window` 在 operator-facing 流中移除
- 但不要求第一阶段立刻从后端 model / storage / result 中完全删除

建议分两步：

1. Phase 1:
   - 前端不再暴露和依赖 window
   - 后端兼容保留 legacy fields
2. Phase 2:
   - 清理 legacy field 依赖
   - 决定是否彻底删除或转 internal-only

## 6. Test and Acceptance Lock

## 6.1 Unit / contract tests

必须新增或更新：

- ROI angle contract tests
- sensitivity contract tests
- temperature confirm contract tests
- ROI-local horizontal point-detection tests
- recapture-on-change tests
- live tracking `A-B` update contract tests

## 6.2 Browser flow tests

必须覆盖：

1. app load 后自动开始 live preview
2. `Freeze` 后拿到可编辑静帧
3. Draw ROI 后自动生成 `A-B`
4. 调整 ROI center / size / angle 后触发重新抓帧和重算点位
5. 调整 sensitivity 后触发重算点位
6. 确认目标温度
7. `Start Live Run` 后实时画面和 `A-B` 持续更新

## 6.3 Operator QA acceptance

当前需求落地的 operator acceptance gate 锁定为：

- 页面启动后无需额外 preview 启动按钮
- `Freeze` 正常保留最后一帧
- ROI 可以拖拽、缩放、旋转
- 右侧 ROI 参数与图上 ROI 双向同步
- 自动点位按 ROI-local horizontal axis 给出左右边界点
- 任意 ROI / sensitivity 改动都会触发新的 still 与新的点位
- 当前温度可见
- 目标温度需确认
- live run 时画面和 `A-B` 都在持续更新
