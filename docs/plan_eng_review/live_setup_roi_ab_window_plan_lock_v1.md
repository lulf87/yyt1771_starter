## Purpose

这份文档把新的 `ROI-first, A-B-before-window` requirement 转成可执行工程计划。

它锁定 5 件事：

1. 该改哪些模块边界
2. live setup 状态顺序要怎么调整
3. API / definition 契约要怎么改
4. 测试和验收 gate 怎么写
5. 分阶段实施顺序是什么

这份 plan 的核心任务不是“继续调 auto-detect 阈值”，而是：

> 把 `ROI 内先找横向或纵向主跨度 A-B` 和 `在 observation window 内做后续观测` 彻底拆成两个阶段。

---

## Review Verdict

当前实现不能在旧逻辑上继续打补丁后直接视为合规。

原因已经锁定：

- 当前 auto detect 依赖 `metric_box / observation_window`
- 当前 auto detect 输出的是预设 window 轴向 extremes
- 这与新 requirement 要求的 `ROI-bound axis-constrained dominant-point detection` 相冲突

因此工程 verdict 是：

1. 必须把 `auto detect` 与 `tracking window` 解耦
2. 必须把 live setup 顺序改成 `ROI -> A/B -> observation window`
3. 必须把 downstream observation direction 显式建模成 `long_axis | short_axis`
4. 在这套分层落地前，不应继续把当前 auto-detect 结果当作 requirement-aligned 行为

## 1. Boundary Lock

### `src.core`

锁定职责：

- final `MeasurementDefinition`
- `ObservationAxis` durable enum / literal
- geometry validation contracts

本轮新增或修订方向：

- `MeasurementDefinition` 继续持有：
  - `analysis_roi`
  - `point_a_px`
  - `point_b_px`
  - `metric_box`（用户语义为 `observation_window`）
- 新增 durable field：
  - `observation_axis = long_axis | short_axis`

禁止放入：

- auto-detect 中间态缓存
- editor 当前选中的工具状态
- preview stream 生命周期

### `src.vision`

锁定职责拆成两类：

1. `ROI-first point detection`
   - 在 `ROI` 内搜索目标物体
   - 支持 guidewire-like / balloon-like 两类 family
   - 输出 `A-B`
   - 不依赖 `observation_window`

2. `window-bounded live tracking`
   - 在 final definition 已存在后
   - 仅在 `observation_window` 内进行后续 measurement / tracking
   - 结合 `observation_axis`

锁定决定：

- 不再让同一个 extractor 同时承担：
  - `ROI-first auto detect`
  - `window-first tracking`
- 当前 `metric_two_point_distance.py` 应被拆成：
  - auto-detect path
  - tracking path
  或至少被重构成两个显式 mode，不得继续混淆

### `src.webapp`

锁定职责：

- live setup editor flow
- preview overlay 交互
- 局部 draft geometry
- action gating

新增 requirement-driven 责任：

- `Draw ROI` 后立即允许：
  - `Point A`
  - `Point B`
  - `Auto Detect Points`
- `Draw Window` 必须基于已有 `A-B`
- `observation_axis` 选择必须体现在 UI 上

### `src.workflow`

锁定职责：

- 只消费 final saved definition
- 不处理 live setup 中间态推导

决策：

- `workflow/live_run.py` 只读最终 definition
- 不在 workflow 内重新猜 `A-B` 或默认 window

## 2. State Flow Lock

## 2.1 Durable run status

`RunStatus` 不新增新的 durable lifecycle enum。

仍然沿用：

```text
created
device_ready
preview_ready
definition_editing
run_ready
running
stopping
completed
failed
invalidated
aborted
```

## 2.2 Editor geometry stage

在现有 `editor.state` 之外，新增一个 webapp-owned geometry progress 微状态：

```text
geometry_stage:
  empty
  roi_defined
  points_defined
  window_defined
  ready
```

语义：

- `empty`
  - 尚无 preview / geometry
- `roi_defined`
  - ROI 已有
  - 允许 manual A/B 或 auto detect
- `points_defined`
  - `A-B` 已有
  - 允许 draw / adjust observation window
- `window_defined`
  - observation window 已有
  - 允许选择 / 修改 `observation_axis`
- `ready`
  - 可保存为 final definition 并进入 `run_ready`

## 2.3 Transition lock

冻结顺序如下：

1. `POST /api/runs`
   - `status=created`
   - `editor.state=empty`
   - `geometry_stage=empty`

2. `POST /preview/frame` 或 `GET /preview/stream`
   - 主状态进入 `definition_editing`
   - `editor.state=editing`

3. ROI 定义完成
   - `geometry_stage=roi_defined`

4. manual `Point A/B` 或 `POST /definition/auto`
   - `geometry_stage=points_defined`

5. `Draw Window`
   - 若尚无 window，必须根据 `A-B` 连线方向生成默认姿态
   - 进入 `geometry_stage=window_defined`

6. 选择 `observation_axis`
   - `geometry_stage=ready`

7. `PUT /definition`
   - 只有 `geometry_stage=ready` 时允许进入 `run_ready`

8. restart preview / freeze
   - 不得清空已定义的 ROI / A-B / window / axis
   - 除非用户显式新建 run 或执行 reset

## 3. API and Config Contract Lock

## 3.1 Canonical v1 endpoint policy

当前阶段不新增第二套 live setup 协议组，仍保留：

- `POST /api/runs/{run_id}/definition/auto`
- `PUT /api/runs/{run_id}/definition`

但契约语义必须调整。

## 3.2 Auto-detect request contract

`POST /definition/auto` 的语义锁定为：

- 输入必须以 `analysis_roi` 为主
- detection params 保留：
  - `foreground_polarity`
  - `threshold_mode`
  - `ignore_internal_texture`
  - `min_target_area_px`
- `observation_window / metric_box` 不能再作为 auto-detect 的必要输入

兼容策略锁定：

- v1 可以继续接受 `metric_box` 字段以兼容旧前端
- 但新实现不得把它作为 auto-detect 的 primary search geometry

## 3.3 Auto-detect response contract

auto-detect 最小返回必须显式表达：

- `point_a_px`
- `point_b_px`
- `quality`
- `detail`

允许附带：

- object span
- target family hint
- advisory message

不要求 auto-detect 直接返回 final observation window。

## 3.4 Final definition contract

最终 `PUT /definition` 保存的 payload 锁定为：

- `analysis_roi`
- `point_a_px`
- `point_b_px`
- `metric_box`（即 observation window）
- `observation_axis`
- detection params

保存前最小校验：

- `ROI` 在图像内
- `A-B` 在 `ROI` 内
- `A != B`
- observation window 在 `ROI` 内
- `observation_axis in {long_axis, short_axis}`

是否强制 `A-B` 也必须位于 observation window 内：

- 当前 plan 推荐：是
- 这样 geometry 更一致，后续 tracking 语义更稳定

## 3.5 Observation-axis config contract

当前实现不得允许自由角度的“观测方向”持久化。

冻结为：

```text
observation_axis:
  long_axis
  short_axis
```

这应成为：

- core model field
- API schema field
- artifact / detail field

## 4. Algorithm Lock

## 4.1 Auto detect is ROI-bounded axis-constrained object detection

合规的 auto detect 必须：

- 在 `ROI` 内找目标物体
- 支持细长弯曲目标与宽主体目标
- 在横向或纵向中选择主跨度更显著的一组点
- 不输出任意斜向直径
- 不依赖预设 observation window 方向

## 4.2 Observation window is not used to discover A-B

`observation_window` 只用于：

- 在 live run 阶段限制 observation aperture
- 对 tracking / measurement 提供后续局部区域

不应用于：

- 初次发现 `A-B`

## 4.3 Default window generation is deterministic

`Draw Window` 默认生成策略必须可重复：

- center: 基于 `A-B` 中点
- angle: 基于 `A-B` 连线角度
- long side: 覆盖 `A-B` 加 margin
- short side: 使用 preset / heuristic default

初值可以 heuristic，但规则必须固定，不得每次漂移。

## 5. Test Lock

## 5.1 Vision unit tests

必须新增或重写的单元测试：

- guidewire-like ROI 内 horizontal-dominant pair detection
- balloon-like ROI 内 horizontal-dominant pair detection
- tall target ROI 内 vertical-dominant pair detection
- curved object ROI 内 axis-constrained pair detection
- no dependence on pre-existing window geometry
- low-confidence advisory path

## 5.2 API tests

必须覆盖：

- `POST /definition/auto` 在只有 ROI 且无 window 时也可工作
- auto detect 不再因为缺 observation window 而失败
- `PUT /definition` 缺 `observation_axis` 时拒绝
- `Draw Window` 后默认 window angle 与 `A-B` 连线一致

## 5.3 Browser / UI tests

必须重新冻结并验证顺序：

1. Create run
2. Fetch / freeze preview
3. Draw ROI
4. Auto Detect Points or manual A/B
5. Draw Window
6. Change observation axis
7. Save definition
8. Start run

至少要验证：

- 不先画 window 也能 auto detect
- auto detect 后 A/B overlay 可见
- Draw Window 基于 A/B 生成默认矩形
- 观测方向只能在 long/short axis 间切换

## 5.4 Non-regression tests

继续保留：

- freeze / restart preview
- new-run state reset
- web 18 fps gate
- mock temp manual stop chain

## 6. Implementation Sequence Lock

后续实施顺序锁定为：

1. `LSW-1` core/schema contract split
   - 加 `observation_axis`
   - 把 auto-detect 输入从 window-first 语义改成 ROI-first 语义

2. `LSW-2` vision extractor split
   - 把 ROI-first point detection 从 tracking extractor 里拆出来

3. `LSW-3` web editor flow reorder
   - `ROI -> A/B -> window`
   - 新增 geometry stage gating

4. `LSW-4` default observation-window generation
   - 基于 `A-B` 生成默认矩形
   - 新增 `observation_axis` UI / persistence

5. `LSW-5` browser regression + image-fixture QA
   - guidewire-like
   - balloon-like

6. `LSW-6` real-camera operator QA
   - verify on real preview frames

在 `LSW-1` 到 `LSW-4` 完成前，不应继续围绕当前 auto detect 点位结果做阈值微调。

## Outcome

这轮 `/plan-eng-review` 的最终锁定结论是：

> 当前 live setup 不应继续沿“observation-window-first auto detect”实现演化。后续实现必须先把 geometry definition 拆成 `ROI-first point detection` 与 `post-A/B observation-window tracking` 两阶段，再在此基础上调整 UI、验证和 real-camera QA。只有在 `ROI -> A/B -> window -> observation_axis` 这条链完整落地后，新的 live setup 才能被视为 requirement-aligned。
