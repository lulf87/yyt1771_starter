## Purpose

这份文档把当前 office-hours 需求基线转成一份真正可执行的工程锁定方案。

重点只锁 5 件事：

1. 模块边界
2. 状态流
3. API / 配置契约
4. 测试方案
5. 分阶段实施顺序

它不是在替代已有详细计划，而是在这些详细计划之上，给出“从现在开始以后不再反复摇摆”的主决策。

## 1. Module Boundary Lock

### `src.core`

锁定职责：

- durable run lifecycle enum
- measurement definition model
- typed runtime config
- cross-module errors / contracts

禁止扩张为：

- preview 推流状态容器
- 浏览器 overlay 编辑状态
- LU92XX 寄存器拼装逻辑

决策：

- `RunStatus` 继续只表示 run 的主生命周期
- preview/editor 微状态不放进 `src.core.enums`

### `src.camera`

锁定职责：

- 打开相机
- 读取 `FramePacket`
- 应用相机级 runtime 参数

禁止承担：

- ROI / A-B / 观测窗口编辑
- PNG / multipart HTTP 编码
- preview 生命周期判断

决策：

- 继续复用现有海康适配器
- 不新增 `camera_service`

### `src.temp`

锁定职责：

- LU92XX Modbus RTU 适配
- `TempReader` + `TempControllerPort`
- 串口 / CRC / 寄存器读写和错误归一化

禁止承担：

- run 状态推进
- API payload 解释
- As/Af 计算

决策：

- 真实设备路径只允许落在 `src/temp/lu92xx_modbus_rtu_controller.py`
- 寄存器、缩放和启动功率都保持 profile-driven

### `src.vision`

锁定职责：

- 基于 `analysis_roi + metric_box + point_a/point_b` 产生 `ShapeMetric`
- auto-detect 建议和 tracking 质量评估

禁止承担：

- HTTP schema
- run gating
- artifact 落盘

决策：

- `metric_two_point_distance.py` 是 live measurement 主实现
- `metric_end_displacement.py` 保留给 replay / legacy flow

### `src.sync`

锁定职责：

- 时间对齐和 snapshot 聚合

禁止承担：

- 调度循环
- 事件总线
- UI 推流

决策：

- 首版 live run 仍是单协调循环
- `SyncHub` 继续只做聚合，不做 orchestration

### `src.curve`

锁定职责：

- AFAS adapter
- `As/Af` 结果计算
- result failure semantics

禁止承担：

- 设备访问
- run 生命周期
- 路由层映射

决策：

- `workflow` 只消费曲线结果，不内嵌 AFAS 细节

### `src.workflow`

锁定职责：

- live run coordinator
- state transition
- finalize pipeline

禁止承担：

- LU92XX 报文细节
- 图像分割 / 跟踪实现
- 前端 overlay 几何编辑

决策：

- `src/workflow/live_run.py` 继续做唯一 coordinator
- preview/editor 微状态属于 webapp 层，不属于 workflow durable state

### `src.storage`

锁定职责：

- summary index
- artifact package
- event / telemetry / result persistence

禁止承担：

- 反向驱动 workflow
- 直接读取硬件

决策：

- SQLite 继续只存 summary index
- live artifacts 继续走 per-session directory

### `src.webapp`

锁定职责：

- API routes
- request / response schema
- preview/editor 微状态
- UI 页面和 overlay 交互

禁止承担：

- 串口命令
- 曲线算法
- 相机 SDK 细节

决策：

- preview stream、freeze 语义、overlay 编辑、action gating 都锁在 `webapp`
- 这里可以持有 preview/editor 的 ephemeral state，但不能反向污染 core lifecycle enum

## 2. State Flow Lock

### 2.1 Durable run status

`RunStatus` 继续使用当前主状态集合，不为 UI 微交互新增新的 durable enum：

```text
created
device_ready
preview_ready
definition_editing
run_ready
running
stopping
completed
failed
invalidated
aborted
```

锁定规则：

- 不新增 `preview_streaming`
- 不新增 `frame_frozen`
- 不新增 `overlay_editing`

这些都不是 run 的 durable lifecycle，而是 preview/editor 微状态。

### 2.2 Preview/editor microstate

新增一个 webapp-owned 的 preview/editor 状态模型，最小字段锁定为：

```text
preview:
  stream_active: bool
  frozen_frame_available: bool
  last_frame_id: int | null
editor:
  state: empty | editing | locked
```

语义锁定：

- `stream_active=true`
  表示当前 run 正在持续预览
- `frozen_frame_available=true`
  表示当前 run 已保留可编辑的最后一帧
- `editor.state=editing`
  表示可在图上编辑 ROI / 观测窗口 / A-B
- `editor.state=locked`
  表示 definition 已形成当前有效版本

### 2.3 Transition lock

主状态与微状态的组合按下面规则锁定：

1. `POST /api/runs`
   - `status=created`
   - `preview.stream_active=false`
   - `preview.frozen_frame_available=false`
   - `editor.state=empty`

2. `GET /preview/stream` 或 `POST /preview/frame`
   - 主状态至少推进到 `preview_ready`
   - 持续流时 `preview.stream_active=true`
   - 单帧抓拍时 `preview.frozen_frame_available=true`

3. `POST /preview/stream/stop`
   - 不清空最后一帧
   - `preview.stream_active=false`
   - `preview.frozen_frame_available=true`
   - 若 definition 未锁定，则主状态为 `definition_editing`
   - 若 definition 已锁定，则主状态保持 `run_ready`

4. `PUT /definition`
   - payload 合法且完整时：`status=run_ready`，`editor.state=locked`
   - payload 合法但不完整时：`status=definition_editing`，`editor.state=editing`
   - payload 非法时：422，不更新当前有效 definition

5. restart preview
   - 允许从 `preview_ready` / `definition_editing` / `run_ready` 重新进入 streaming
   - 不要求页面刷新
   - 不自动清空已冻结 definition

6. `POST /start`
   - 只有 `status=run_ready` 时允许
   - 如 preview 仍在 streaming，先停止 preview，再进入 `running`

7. operator stop
   - `running -> stopping -> aborted`

8. invalid tracking
   - 若 `stop_on_invalid_tracking=true`：
     `running -> invalidated -> stopping -> aborted`

9. execution / finalize error
   - 进入 `failed`

10. normal finalize
    - 进入 `completed`

11. new run
    - 必须重置旧 run 的 preview/editor 微状态
    - 不允许旧 overlay 或旧 frozen frame 泄漏到新 run

## 3. API Contract Lock

### 3.1 Canonical v1 endpoints

v1 继续锁定下面这组端点，不在当前阶段改协议形状：

- `POST /api/runs`
- `GET /api/runs/{run_id}`
- `PUT /api/runs/{run_id}/definition`
- `POST /api/runs/{run_id}/definition/auto`
- `POST /api/runs/{run_id}/preview/frame`
- `GET /api/runs/{run_id}/preview/stream`
- `POST /api/runs/{run_id}/preview/stream/stop`
- `POST /api/runs/{run_id}/start`
- `POST /api/runs/{run_id}/stop`
- `GET /api/runs/{run_id}/telemetry`
- `GET /api/runs/{run_id}/result`

锁定决定：

- v1 API 名称保留 `POST /definition/auto`
- UI 文案可以叫 `Auto-detect`
- 当前阶段不为了文案一致性把端点改成 `/definition/auto-detect`

### 3.2 Run detail response

`GET /api/runs/{run_id}` 对前端必须成为唯一可信状态入口。

因此锁定最小扩展为：

```text
RunDetailResponse:
  run_id
  status
  profile
  preset
  definition
  created_at_ms
  updated_at_ms
  definition_complete: bool
  preview:
    stream_active: bool
    frozen_frame_available: bool
    last_frame_id: int | null
  editor:
    state: empty | editing | locked
```

理由：

- 前端不能再靠“本地 DOM 是否还有图”推断 freeze 状态
- stop/restart 语义必须从 API 可见状态恢复

### 3.3 Preview contract

preview 路径锁定如下：

- `POST /preview/frame`
  - 作为抓拍 / 冻结兜底路径保留
  - 返回单张 `image/png`
- `GET /preview/stream`
  - 继续使用 `multipart/x-mixed-replace`
  - 不升级成 WebSocket
- `POST /preview/stream/stop`
  - 语义为“停止推流，但保留最后一帧可编辑”
  - 绝不清空当前 frozen frame

### 3.4 Error mapping

当前阶段的 HTTP 语义锁定为：

- `404`
  - missing run
- `409`
  - preview stream already active / conflicting active operation
- `422`
  - invalid geometry / invalid definition / invalid transition
- `503`
  - camera or preview runtime unavailable

### 3.5 Artifact and telemetry contract

当前阶段继续锁定：

- telemetry 走 `GET /telemetry`
- result 走 `GET /result`
- preview 状态不混入 result payload
- measurement definition 作为 artifact 保存，不自动写回 profile

`RuntimeConfig.live` 继续锁定为：

```text

  vision:
    foreground_polarity

    edge_threshold
    ignore_internal_texture
    min_target_area_px
    quality_threshold
  analysis:
    engine
    channel_name
    as_fit_point_count
    af_fit_point_count
  run:
    preview_poll_ms
    telemetry_poll_ms
    capture_interval_ms
    stop_on_invalid_tracking
```

### 4.2 Ownership rules

- `camera.device_roi`
  只表示设备侧裁剪，不等于 operator 的 `analysis_roi`
- operator 定义的 `analysis_roi / metric_box / point_a_px / point_b_px`
  只存在于 `MeasurementDefinition`
- `temp.register_map` 和 `temp.control`
  继续是 profile-driven
- `analysis.channel_name`
  继续锁定为 `Space1`
- `analysis.engine`
  继续锁定为 `afas`

### 4.3 Config non-goals

当前阶段不允许：

- 把 operator ROI 持久化成 profile 默认值
- 把 preview/editor 微状态写进 profile
- 在 route 或 workflow 里硬编码 LU92XX 寄存器地址

## 5. Test Plan Lock

### 5.1 Architecture tests

必须继续保证：

- route 不直接依赖硬件实现
- workflow 不直接写 LU92XX 寄存器
- curve 不被 webapp 直接绕过

### 5.2 API tests

至少补齐下面这些断言：

- `GET /api/runs/{run_id}` 返回新的 preview/editor 微状态
- `POST /preview/stream/stop` 后 `frozen_frame_available=true`
- stop 后再次 start stream 无需刷新页面
- `POST /definition/auto` 仍是 canonical v1 endpoint
- invalid definition 不会覆盖当前有效 locked definition

### 5.3 Browser tests

必须把这些场景视为 ship gate，而不是 nice-to-have：

- stop preview 后最后一帧仍可见
- 同一 run 上 restart preview 成功
- ROI / 观测窗口 / A-B overlay 可见
- 新建 run 后旧 overlay / 旧 frozen frame 被正确清理
- run button 只在 `run_ready` 时可用

### 5.4 Integration tests

必须继续覆盖：

- completed run
- invalid tracking path
- operator stop path
- finalize result failure
- artifact write/readback

### 5.5 Bench validation

真实 LU92XX bench 只在下面前置条件满足后才继续：

- Phase 2 freeze-first UI 语义已经闭环
- API / browser regression 已通过
- no-refresh restart 行为稳定
